# Colour

Rules first, hexes second. `src/styles/tokens.css` is generated by
`scripts/color/emit.mjs`; `npm run color:check` proves the gates still hold.
Never hand-edit the token file — change a rule and regenerate.

## The rules

**1. Steps are perceptual, not RGB.** Every ramp is built in OKLCH with fixed
lightness targets, so a step looks like the same size step in any hue. Picking
hexes in RGB or HSL gives ramps that lurch. (Maureen Stone, _A Field Guide to
Digital Color_; Ottosson's OKLab.)

**2. Twelve steps, each with one job.** 1–2 backgrounds, 3–5 component fills,
6–8 borders, 9–10 solids, 11–12 text. A colour is chosen by the role it plays,
never by how it looks in isolation.
([Radix Colors](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale))

**3. Surfaces layer, and a control sits one layer above its ground.** A field on
layer 2 takes layer-3 tokens, and its border matches its field number.
([IBM Carbon](https://carbondesignsystem.com/elements/color/usage/))

**4. 3:1 for anything meaningful that isn't text; 4.5:1 for text.** Bar fills,
the empty track, focus rings and control boundaries are graphical objects, so
they are gated, not eyeballed.
([WCAG 2.2 SC 1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html))

**5. No neutral greys.** Every neutral carries a little chroma at the theme's
hue — 285° for Glass, 75° for Bento, 250° for Minimal, 155° for Console. Pure
grey next to a tinted accent reads as dirty. (Wathan & Schoger, _Refactoring
UI_.)

**6. Colour carries data; grey carries structure.** Surfaces, rules and labels
stay neutral so the only saturated things on screen are the ones that mean
something. (Tufte, _The Visual Display of Quantitative Information_.)

**7. Contrast of extension.** A small area of intense colour balances a large
quiet one, so the accent appears only on small marks — a bar, an icon, an
active tab — and never as a large fill. (Itten, _The Art of Color_.)

**8. Colour is relative to its ground.** The same value reads differently
against different backdrops, which for a translucent widget means the user's
wallpaper. Contrast is therefore guaranteed by the widget's own surface
opacity, not by hoping the desktop behind is friendly. (Albers, _Interaction of
Color_.) This rule exists because we broke it: footer text measured about
1.1:1 over a mid-grey desktop.

**9. Status hues are reserved and never carry identity alone.** Every state
ships an icon and a word beside the colour. (WCAG SC 1.4.1.)

**10. Accents stay out of the status band.** Status occupies 23°–85°, so accents
live at 195°–330° — at least 110° away. There is deliberately **no green
accent**: it would collide with a success hue.

**11. Severity is ordinal, so it ramps.** `ok → tight → near limit → limit hit`
is an ordered scale, not four categories. Running amber, orange and red as
peers fails badly — measured ΔE 0.7 between warn and serious under deuteranopia.
Instead lightness moves monotonically with severity (darker as it worsens in
light mode, brighter in dark mode) and hue follows along. Ordered data gets an
ordered encoding.

## Assignments

| Role                 | Step            | Why                                 |
| -------------------- | --------------- | ----------------------------------- |
| Widget surface       | 2, at 82% alpha | Rule 8: opacity carries contrast    |
| Raised tile          | 3               | Rule 3: one layer above its ground  |
| Meter track          | 4               | Searched, not chosen — see below    |
| Border, focus ring   | 7               | Rule 2                              |
| Muted text           | 10              |                                     |
| Secondary text       | 11              | Rule 2, ≥4.5:1                      |
| Primary text         | 12              |                                     |
| Bar fill, active tab | 10              | Rule 7: small areas, full intensity |

The track is step 4 rather than the more natural step 5 because amber is the
lightest hue on the wheel: at step 5 the `tight` fill measured 2.80:1 against
its own track and failed rule 4. The pairing was found by enumerating every
fill/track combination and keeping only those clearing 3:1 in both modes —
`scripts/color/` does this, and eleven combinations passed.

## Checking it

```
npm run color:check
```

Prints every gated pair in both modes and exits with the failures listed. If you
change a lightness target, a hue, or a role assignment, this is the thing that
tells you whether you broke it.
